# 2026-10-12

## 给 README 配界面截图

产出：`docs/screenshots/` 下 4 张真实界面截图（2560×1720，2x），README 里新增 hero 图 +
「界面预览」小节（代码/公式、图片/文件、大图预览）。

抓图方式（可复用，脚本留在 `/tmp/shot/capture.mjs`，未入库）：

- **假 IP 代理**：server.js 的 `normalizeClientIp()` 会读 `x-forwarded-for`，
  所以给每个「虚拟客户端」起一个本地 HTTP 代理（HTTP + `upgrade` 两条路径都要转发，
  都要塞 header），把 `127.0.0.1` 换成 `192.168.1.10x`。否则三个客户端在侧栏里
  全显示成同一个 IP。
- **驱动**：无头 Chrome + 裸 CDP（Node 22 自带 WebSocket，不装 Playwright）。
  `/json/new?...`（要 `PUT`）多开 target，`Page.captureScreenshot` 出图，
  `Emulation.setDeviceMetricsOverride{deviceScaleFactor:2}` 出 2x 图。
  发消息走真实路径：往 `#msg-input` 里塞值 + 点 `#send-btn`；发文件用
  `DOM.setFileInputFiles` 打 `#file-input`。
- 坑：`Browser.close` 会关掉整台浏览器（把 3 个客户端页面一起干掉），
  只能 `/json/close/<targetId>` 关单个 target；页面关掉时 ws 会 ECONNRESET，
  要给 ws 挂 `onerror`，否则脚本直接崩。
- 坑：**假 IP 会毁掉 P2P**——p2p.js 的 mDNS 候选改写用的是服务端转发的对端 IP，
  改成 `192.168.1.10x` 这种本机不存在的地址后直连必然失败。所以截图只拍
  「点击接收」的初始卡片状态，没有真跑一次传输。

侧栏里多出来的 `192.168.0.209` 不是 bug：那是用户自己本机的浏览器开着页面连上来的
（本机局域网 IP 就是 192.168.0.209），抓图时正好一起出现在在线列表里。
