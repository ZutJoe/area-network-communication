## 消息支持代码块（area-network-communication）

用户反馈：粘贴代码后消息气泡里被压成一行、完全没法读。**根因有两个，缺一不可**：

1. `<input type="text">` 是单行输入框，粘贴多行代码时换行在浏览器侧就被丢掉了 —— 这才是截图里"挤成一行"的真凶。
2. 渲染用 `textContent` + 默认 `white-space: normal`，即便有换行也会被折叠。

### 改动（index.html，单文件）
- 输入框 → 自适应高度的 `<textarea>`（最多 180px 自动长高）；Enter 发送、Shift+Enter 换行；**必须判断 `e.isComposing` / `keyCode !== 229`**，否则中文输入法候选框上按回车会误发。
- 新增 `insertCodeBlock()`：输入框旁 `</>` 按钮，有选区就包一层围栏，无选区就插入一对空围栏并把光标放中间。
- 文本渲染改为 `renderMessageBody()`：先 `parseSegments()` 拆成 [文本/代码] 片段，普通消息仍走原来的 `.msg-text`（加了 `white-space: pre-wrap` 保留换行）；含代码的消息外层用 `.msg-body` 容器。
- 围栏解析：`/(?:^|\n)[ \t]*```([^\n`]*)\r?\n?([\s\S]*?)```/g`。**围栏必须行首**（仿 CommonMark），否则聊天里说"用 ``` 包起来"会误触发代码块（视觉验收时就踩到了）。未闭合围栏按"到结尾都是代码"处理。
- 无围栏时自动识别：`looksLikeCode()` 打分制（阈值 3），中文占比 > 12% 直接判为人话，避免把正常聊天变代码；`guessLang()` 按内容猜语言。
- 高亮：自研轻量 tokenizer（`R` 规则表 + `KW`/`BI` 关键字表 + `profileOf()` 语言配置），**不依赖任何 CDN**（局域网/断网可用）。主正则 5 个捕获组固定顺序 comment|string|number|accent|word，用 `/(?!)/` 占位表示"该语言没有这条规则"。逐个 token `createTextNode`/`createElement` 建节点，天然免疫 XSS（`<img onerror>` 只会当文字显示，已验）。
- 代码块 UI：语言标签 + 「复制」+「文本」（本地按纯文本显示，识别错了的逃生口，不影响别人）。复制走 `navigator.clipboard`，**局域网 http 是非安全上下文、clipboard 为 undefined，必须有 execCommand 兜底**。
- `const socket = (typeof io === 'function') ? io() : {on(){},emit(){}}` —— 原来 `io()` 直接调用，socket.io 加载失败时整个脚本挂掉，页面全白。

### 可复用的验收手法（本次靠它抓到 3 个 bug）
1. **纯逻辑单测**：把 index.html 里的内联 `<script>` 抠出来，用 `vm.runInContext` + 手写最小 DOM stub（`createElement/createTextNode/createDocumentFragment/querySelector` 都要返回对象，`querySelector` 返回 null 会误报错）跑，再把渲染树序列化成字符串断言。比自己手推正则靠谱得多。
2. **视觉验收**：生一个临时页——把 `<script src="/socket.io/socket.io.js">` 换成 `window.io` 桩，末尾注入 `appendMessage()` 假数据；再用本机 Chrome 无头截图：
   `"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless --disable-gpu --hide-scrollbars --window-size=1180,1800 --virtual-time-budget=3000 --screenshot=out.png "file:///tmp/.../preview.html"`
   然后 Read 那个 png 肉眼看。**坑**：注入的假数据里只要有 `</script>` 字面量，外层 script 会被 HTML 解析器提前截断，必须写成 `<\/scr'+'ipt>`。
3. agent-browser 未安装、且不能 `npm install -g`，用 Chrome 无头最省事。

## 追加：改成完整 Markdown 渲染（同日晚些）

用户要求：不要 `</>` 按钮，输入时写 Markdown 语法、发出去自动渲染。

- **删掉** `insertCodeBlock()` 与输入框旁的 `</>` 按钮；`parseSegments` 整套片段拆分逻辑被 Markdown 解析器取代（`parseBlocks` / `parseList` / `renderInline` / `inlineWithBreaks` / `renderMarkdown`）。
- 渲染统一进**一个气泡** `.msg-text`：原来「文本段独立气泡 + 代码块在外」的 `.msg-body` 布局已废弃（CSS 里的 `.msg-body` 规则一并删除）。`.msg-text` 的 `white-space: pre-wrap` 必须去掉，否则块级元素之间会冒出空白；换行改由段内 `<br>` 显式处理。
- 支持子集：标题、粗/斜/删除线、行内代码、围栏代码块、有序无序列表（可嵌套）、引用（可嵌套）、表格（含对齐）、分割线、链接/图片/裸链接、转义。`~~~` 围栏也认。
- 安全：链接只放行 `http/https/mailto/ftp`，`javascript:`/`data:` 降级成纯文本（这是 Markdown 渲染最容易被忽略的 XSS 入口）；图片只放行 `https?`，且 `onerror` 降级成链接（否则聊天里留个破图标很难看）。
- 保留「裸代码自动识别」：`!FENCE_OPEN_RE.test(src) && looksLikeCode(src)` 时整块按代码渲染。顺序很关键——**自动识别必须在 Markdown 之前判断**，否则 python 里的 `# 注释` 会被当成 ATX 标题渲染成 h1。
- 「文本」逃生口现在只在语言是**猜的**时候出现（整段自动识别、或围栏没写语言）；明确写了 ` ```python ` 就不给，减少按钮噪音。

### 又踩到两个坑（都被测试台抓到）
1. **`renderInline` 递归 + 共用全局正则 = 死循环**：强调语法要递归调用自身，内层 `re.lastIndex = 0` 会把外层游标冲掉，外层 `exec` 从错误位置继续 → 反复匹配同一 token → 堆爆掉（node OOM 崩了 4GB）。修法：每次调用 `new RegExp(INLINE_RE.source, 'g')` 用独立实例。
2. **裸链接正则吃中文标点**：`[^\s<>()"']+` 会把 `https://github.com/x/y，还有` 整段吞进 href。改成只吃 ASCII URL 字符集 `[A-Za-z0-9\-._~:\/?#\[\]@!$&*+,;=%]+`，再单独剥离结尾标点。

单测扩到 20 项（含表格/嵌套列表/嵌套引用/转义/危险链接/空内容），全过。

## 追加 2：公式渲染（KaTeX，同日晚些）

用户问「公式能不能渲染」。手写 TeX 排版不现实，选用 **KaTeX 作为本地 npm 依赖**（`npm install katex`，4.3MB 含字体），由 server.js 的 `express.static('.')` 直接提供 `/node_modules/katex/dist/…`——**刻意不引 CDN**，保持「纯局域网/断网可用」这个既有前提。已 curl 验证 css/js/字体均 200。

- `<link>` + `<script>` 引 KaTeX；`buildMath()` 里 `typeof katex === 'undefined'` 时**降级为显示 LaTeX 源码**（和 socket.io 的守卫一个思路），`katex.render` 也包了 try/catch。
- KaTeX 选项：`trust:false`（禁用 `\href`/`\includegraphics` 这类可外链或注入的宏）、`maxExpand:1000` + `maxSize:20`（防 `\def` 递归把浏览器卡死）、`throwOnError:false`（写错标红不崩）。
- 行内 `$…$` 的正则：`\$(?<math>[^\s$](?:[^$\n]*[^\s$])?)\$(?!\d)`——开头非空白、结尾非空白、收尾 `$` 后不跟数字，这样「这个 $5 到 $10 之间」不会被误判成公式。
- ~~**公式在 INLINE_RE 里必须排在强调语法之前**~~ **更正（当天验证）：这条是错的。** 正则取「最靠左」的匹配，只有同一起点才按分支先后试；`$` 本来就在 `_`/`*` 左边，所以分支顺序不影响结果。我用 Edit 把公式挪到最后一位跑测试，36 项照样全过。代码注释已改成实话，别再把顺序当必要条件。
- 块级 `$$…$$` 走 `matchMathBlock()`，支持跨行、未闭合也照收；`isBlockStart` 要认得 `$$`，否则会被上一段吞掉。
- `renderMessageBody` 里加了 `HAS_MATH_RE` 让路：带公式的消息不参与「裸代码自动识别」（否则 `$` 会被当代码）。shell 里的 `$VAR` 不含成对 `$`，不受影响。

### 第 3 个坑（这次在测试工具里，不在应用里）
演示页数据里所有 `$$` 都变成了 `$`，排查半天以为是解析器 bug，最后发现是 **`String.prototype.replace` 的替换串里 `$$` 会被折叠成一个 `$`**（`$&`/`` $` ``/`$'`/`$1` 也有特殊含义）。演示页用 `html.replace('</body>', demo)` 注入数据，就把公式全改坏了。**修法：替换串涉及用户数据时一律用函数式替换 `replace(x, () => y)`**。以后写这类生成脚本直接照这个来，别再用字符串替换串。

## 收尾 3：把 index.html 的内联脚本拆成 ES 模块（用户要求「不同功能放不同文件」）

`index.html` 从 1295 行降到 128 行，1168 行内联脚本拆成 `js/` 下 14 个文件 + 1 个标记用 `package.json`。

拆分结果（依赖单向、无环）：`main.js`（入口，只做装配 + socket 事件路由）／`socket.js`（全项目唯一持有 socket 实例）／`dom.js`（元素引用 + 通用工具）／`compose.js`（输入区）／`users.js`（在线列表）／`messages.js`（通用消息）／`markdown.js`（Markdown + 消息正文入口）／`highlight.js`（高亮 + 猜语言 + 像不像代码）／`code-block.js`（代码块 UI）／`math.js`（KaTeX）／`clipboard.js`／`image.js`（小图 base64 直发）／`p2p.js`（WebRTC 直传 + 信令 + mDNS 改写）／`lightbox.js`。

**关键决策与坑：**

- **HTML 里的 `onclick="sendFile()"` 必须改掉**（改成 `#file-btn` + `initCompose()` 里绑监听）。模块化后函数不再是全局的，内联事件属性会**静默失效**——不报错，点了没反应。
- **`file://` 打不开 ES 模块**（CORS）。原来「双击 `test/preview.html` 就能看」的离线预览必须改成经 `npm start` 后访问 `http://localhost:3000/test/preview.html`。这是**行为变化，已写进 README**，别当成 bug。
- **Node 跑测试会报 `MODULE_TYPELESS_PACKAGE_JSON`**。正确修法是加 `js/package.json` = `{"type":"module","private":true}`（标记子目录为 ESM）；**不要**给根 package.json 加 `type: module`（会把 `server.js` 等 CJS 弄坏），也别改成 `.mjs`（浏览器侧要额外确认 MIME）。
- **`navigator` 在 Node 21+ 是只读 getter**，测试里 `globalThis.navigator = {}` 会静默失败，必须 `Object.defineProperty(..., {writable:true, configurable:true})`。也不要整体覆盖 `globalThis.URL`，只补 `URL.createObjectURL`。
- **搬运无损校验**：先把内联脚本存 `/tmp` 做基线，改完按函数名（花括号配对）逐个比对紧凑化后的文本。50 个函数里 48 个逐字一致，2 个只差把随机 token 抽成 `dom.js` 的 `makeToken()`。这招比肉眼看出错靠谱得多。
- **`test/render.test.js` 改造**：从「vm 里跑抠出来的脚本」改成「globalThis 装 DOM 桩 + `await import()`」。先 import `main.js` 走一遍完整模块图，路径/导出写错会立刻炸。断言数 36 → 37（新增一条验证 `appendMessage` 确实挂到 `dom.js` 导出的 `#messages` 上，防止容器接线断了没人发现）。
- **浏览器实测**（无头 Chrome）：先用 `--dump-dom` 打预览页，成功；但打首页时**永不返回**——因为 socket.io 长连接让 `--virtual-time-budget` 不生效，命令跑到后台超时。改用 **CDP**（Node 22 自带全局 `WebSocket`，不用装任何包）拿到：无 JS 异常、`userItems=3`、系统「加入了」消息已渲染、`send-btn`/`file-btn` 的 `onclick` 都是 function、KaTeX 已加载。唯一 404 是 `favicon.ico`，**改造前就有**（HTML 没写 `<link rel="icon">`）。
- 顺便把「拆内联脚本 + 不装 Playwright 实测页面」沉淀成技能 `~/.workbuddy/skills/inline-js-to-esm/`（含 `diff-moved-functions.js` 与 `cdp-check.mjs`，两个脚本都用本项目跑通验证过；cdp-check 第一版有 favicon 噪声和类名按钮假阴性，已修）。
